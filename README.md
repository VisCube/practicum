# Голосовой ассистент контакт-центра УК

Голосовой ассистент принимает обращения, отвечает на вопросы, собирает данные для заявок и при необходимости переводит звонок оператору. Дев-стенд работает в браузере; сервер предоставляет HTTP API и голосовой WebSocket.

## Установка и локальный запуск

Требуются Git и Python 3.12 или новее.

```bash
git clone --recurse-submodules -b feat/demo-stand https://github.com/VisCube/practicum.git dispatcher
cd dispatcher
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[cloudru,dev]"
cp .env.example .env
# Укажите настройки Cloud.ru в .env
python3 -m assistant.main
```

Перед запуском выберите Cloud.ru в `.env` и заполните ключи, как описано ниже. Откройте `http://localhost:8000/debug/`. Не публикуйте `.env` и ключи в репозитории.

Если репозиторий уже склонирован без подмодуля, из его корня выполните:

```bash
git submodule update --init --recursive
```

После переключения на версию проекта с другим коммитом подмодуля повторите эту команду. Она загружает версию, зафиксированную в основном репозитории, а не обязательно последнюю версию автора.

## Конфигурация

Настройки берутся из `.env`; полный список и примеры — в `.env.example`.

- `DIALOG_ADAPTER`: `rules` или `cloudru`.
- `ASR_ADAPTER`: `fake`, `vosk`, `t-one` или `cloudru`.
- `TTS_ADAPTER`: `fake`, `piper`, `silero` или `cloudru`.
- `LLM_ADAPTER`: `fake`, `openai` или `cloudru` для диалога на правилах.
- `CRM_ADAPTER`: `fake` или `telegram`.

Основная конфигурация проекта — Cloud.ru: укажите `DIALOG_ADAPTER=cloudru`, `ASR_ADAPTER=cloudru`, `TTS_ADAPTER=cloudru` и настройки `FM_API_KEY`, `FM_BASE_URL`, `LLM_MODEL`, `STT_MODEL`, `RAG_KEY_ID`, `RAG_KEY_SECRET`, `RAG_BASE_URL` и `IAM_TOKEN_URL` в соответствии с используемыми компонентами. Для локальных ASR/TTS и классификатора нужны соответствующие дополнительные зависимости и файлы моделей — их пути приведены в `.env.example`.

Журнал звонков настраивается переменными `CALL_LOG_*` в `.env.example`. Для SQLite и резервных копий используйте постоянное хранилище; журнал может содержать персональные данные.

## Docker

Перед сборкой инициализируйте подмодуль, как показано выше. Сборка с Cloud.ru:

```bash
docker build --build-arg EXTRAS="cloudru" -t dispatch:cloudru .
```

Доступные наборы зависимостей указаны в `Dockerfile` и `pyproject.toml`. При использовании Docker Compose подключите постоянные тома для журнала и резервных копий. После изменения кода или версии подмодуля пересоберите образ.

## Устройство проекта

- `src/assistant/api/` — HTTP-маршруты, голосовой WebSocket и браузерный стенд.
- `src/assistant/core/` — конфигурация, модели и управление диалогом.
- `src/assistant/handlers/`, `nlu/` — обработчики и распознавание намерений для диалога на правилах.
- `src/assistant/services/` — адаптеры распознавания, синтеза, CRM, телефонии и LLM.
- `src/assistant/services/cloudru/_upstream/` — авторский код как Git-подмодуль; обвязка находится рядом, за его пределами.
- `data/` — конфигурация классификатора, эскалаций и база знаний.
- `tests/` — автоматические тесты.

Авторский подмодуль обновляется до конкретного коммита; перед фиксацией новой версии проверяйте совместимость обвязки и бизнес-действия, включая заявки и перевод оператору. Тесты не гарантируют совместимости при изменении поведения автора.

## Тесты и проверки

```bash
pytest tests/unit
ruff check src tests
ruff format --check src tests
mypy src/assistant
```

Для запуска проверок установите зависимости `dev`. Для реальной проверки Cloud.ru нужны настроенные доступы; автоматические тесты не заменяют проверку звонка и озвучивания.

## Основные ограничения

- Сессии хранятся в памяти процесса; для горизонтального масштабирования требуется внешнее хранилище.
